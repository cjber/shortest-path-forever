# AGENTS.md

Shortest Path Forever is a WoW: Forever addon (Interface 16001) that plans and guides journeys by foot, flight, boat,
lift, tram and portal. It needs ForeverCore (declared in `## OptionalDeps`; the release pinned in `tools/forever-core.txt` ships in the zip),
which owns the tracker column, report window, error journal, settings chrome and map canvas. The BigWigs packager ships
bundled compressed terrain as one addon on a `v*` tag.

## Commands

```sh
python3 tools/doctor.py             # first on a new machine: every tool pin, with a fix for each problem
python3 tools/gate.py               # the fast local gate: format, lint, typecheck, specs, generated data, changelog, rules
python3 tools/gate.py --changed     # only the steps the diff against origin/main reaches
```

`gate.py` loads ForeverCore from `$FOREVER_CORE`, else `../forever-core`: set it in a worktree. CI adds the simulator,
the benches (`tests/journey_bench.lua`, `hearth_savings_bench.lua`, timed by Speedpatrol; the 3 ms worst-frame budget
is local, `SPF_BENCH_STRICT=1`), `tests/ui.sh`, shellcheck, shfmt, the package build, actionlint, zizmor and gitleaks.
A change's player-facing notes go in `changes/<issue>.md`; only the release commit edits `CHANGELOG.md`
(`python3 tools/changelog.py release X.Y.Z`). Release: `.agents/skills/release/SKILL.md`.

## Layout

- `Data/*.lua` is generated by `tools/gen_routes.py`, `gen_transit.py`, `gen_towns.py`, `gen_services.py`,
  `gen_targets.py` and `bake_walks.lua`; never hand-edit. `Nav/` holds the compressed walking maps built by
  `tools/baker/` and `tools/pack_nav.py`; terrain is decoded only when a route needs it.
- Pins `BUILD` (`tools/gen_routes.py`) and `INFLIGHT_REV` (`tools/gen_transit.py`) follow upstream: `refresh-data.yml`
  runs `tools/refresh_pins.py` daily and opens a `data/refresh` PR (`retry-refresh.yml` re-runs a failure once, then
  files "Data refresh failed"). Moved by hand: `DB_REV` (classic-db, frozen under the WFA-28 waivers), the Blizzard UI
  pin in `tools/forever_sim/fetch.py` (moves with forever-core), `tools/fetch_blizzard_ui.sh`'s checksummed source, and
  the walking maps, which need a local client install.
- `Core/` lifecycle, ForeverCore registration, the planning context and the public API. `Routing/` transport search,
  walking-map decoding, the player's height band, scheduling. `Journey/` state, steps, costs, guidance, corpse
  recovery (budgets in `tests/journey_performance.md`). `Transport/` the live timetable, taxis, teleports.
  `UI/` map overlays, services, tracker, compass, menus, settings.
- `Locales/enUS.lua` makes `L`, keyed by the English phrase (`Locales/README.md`); `python3 tools/phrases.py >
  Locales/phrases.txt` after a phrase change. `docs/curseforge.md` is the store description.
- `tools/forever_tools/` and `tools/forever_sim/` are vendored from forever-core: never edit them here.
  `tools/data_report.py --base REV` reports keyed data changes.

## Rules

- Lua 5.1 in the game's sandbox: no `require`; a new file goes in `ShortestPathForever.toc` or never runs.
- Specs load ForeverCore first through `tests/forever_core.lua`, so they exercise the real shared modules. Frames,
  menus, tooltips and the tracker are checked in the headless client (`wow-forever-addon` `in-game.md`); the PR
  lists what was checked.
- A flight point is known only when its flight-master slot is CURRENT or REACHABLE; DISTANT is undiscovered on this
  client (`tests/taxi_known_client_spec.lua` guards the fixture).
- Searches and tracker updates wait until combat ends; no idle `OnUpdate` (the map view in `UI/Canvas.lua` runs one
  only while the map is open, where the map itself runs one).
- Draw on the world map only through `UI/Canvas.lua`: our own frames on the canvas, never `AddDataProvider`,
  `AcquirePin`, `AddOverlayFrame` or any other write into the map (#158; `tests/ui_map.lua` fails on one).
- Keep tracker sections in the shared column: create the module, set `safeCall`, `legacySettings` and
  `AddHeaderMenuEntries`, attach with `ForeverCore.TrackerHost.Attach`; never register with Blizzard's tracker manager.
  Render only after `PLAYER_ENTERING_WORLD` and `VARIABLES_LOADED`, deferred one frame; this supersedes WFA-5's native
  registration guidance. Test event ordering and reuse.
- Never touch Blizzard's Lua state (WFA-38); restyle a Blizzard element by drawing on top of it.
- Never stretch art: draw at native aspect through `UI/Art.lua` (`Art.Fit`, `Art.Icon`); `tools/lint_art.py` refuses a
  raw `SetAtlas`/`SetTexture` elsewhere unless its line says `-- art-ok: reason`.
- New runtime globals go in `.luacheckrc` with real types (Ketho's annotations, the defining addon class, or
  `types/*.lua`); no blanket allowlist. Generated annotations belong in the generator. A trailing `select(...)` is
  parenthesized or carries `-- multi-value: reason`.
- Before cleanup, dead-code or refactoring work, read the live roots and settled shapes in `.sloppatrol/instructions.md`.

## Waivers

Each is a WFA-28 exception: data neither QuestieDB nor AtlasLoot holds, from wago.tools tables at the pinned build plus
CMaNGOS classic-db where named. Live client values win wherever the client offers one.

- `Data/Routes.lua` (boat and zeppelin routes, docks, periods): `TaxiPathNode` timed by the mangos-classic transport
  model and stretched onto classic-db `transports.period`; QuestieDB's object `waypoints` is empty. Sightings set phase.
- `Data/Transports.lua` (lifts, Deeprun Tram): `TransportAnimation` placed at classic-db `gameobject` spawns with
  hand-curated site names and car pairings. `guardedFaction` comes from per-site NPC witnesses in `tools/gen_transit.py`
  `LIFT_GUARDS`, validated against classic-db `creature` and the client's `FactionTemplate`: a default boarding-safety
  policy, curated, not inferred by radius; classic-era spawns establish neither live Forever guard positions nor PvP safety.
- `Data/Taxi.lua` (flight points, paths, durations, island bounds): `TaxiNodes`, `TaxiPath`, `TaxiPathNode`,
  `UiMapAssignment`, `Map`; durations from InFlight's defaults, two hand-drawn Feralas boxes. Known points and names
  are read from the flight map.
- `Data/Portals.lua` portals and passages: `AreaTrigger` with classic-db `areatrigger_teleport`, six hand-picked.
- `Data/Portals.lua` `ns.Entrances` (instance doors): the instance's corpse point in `Map` (`CorpseMapID`,
  `Corpse_0/1`), or for Naxxramas its `AreaTrigger`; a door on no outdoor `UiMapAssignment` zone is left out.
- `Data/Zones.lua` (zone level ranges, capitals' sides, map boxes): published ranges typed into `PUBLISHED_LEVELS`
  in `tools/gen_transit.py` from Warcraft Wiki; Forever's zones take `AreaTable.ExplorationLevel`; capitals' zones in
  `CAPITAL_ZONES`. The zone of a point is always `C_Map.GetMapInfoAtPosition`.
- `Data/TownAreas.lua` (ground a hostile town's flight master stands in): CASC ADT tile MCNK `AreaTable` ids via
  `tools/gen_towns.py`; `Journey/Hazards.lua` falls back to a radius where the area is not a sub-area (#719).
- `Data/Services.lua` (food and drink, profession goods, trainers, mage portal trainers, battlemasters): `ItemSparse`,
  `ItemXItemEffect`, `SpellEffect`, `SkillLineAbility` and related tables with classic-db vendor, trainer and
  battlemaster tables; QuestieDB's `foodType` is 0 for every vendor item and it has no trainer spells.
- `Data/SpellTargets.lua` (spells and on-use items that target another unit): `SpellEffect.ImplicitTarget`,
  `SpellMisc`, `SpellRange`; `Routing/Band.lua` asks `C_Spell.IsSpellInRange` and `C_Item.IsItemInRange` only for these.
- `Data/Heights.lua` and `Data/IdleSpawns.lua` (spawn heights, idle NPCs): classic-db `creature` and `gameobject`
  spawns matched to walking-map surfaces by `tools/bake_heights.lua`; QuestieDB's spawns have no height or movement type.
- `Data/Teleports.lua` (class teleports, bind items): spell and item tables with `spell_target_position` landings;
  known spells, reagents, cooldowns and the bind point are read from the client.
- `Data/Walks.lua` and `Nav/` (walking costs, maps): baked from a local client install's terrain by
  `tools/bake_walks.lua` and `tools/baker/`. `Data/RoadCells.lua` and `Data/RoadEdges.lua` (roads): `tools/gen_roads.py`
  reads ADT texture layers from wago.tools' CASC mirror (33 road textures checked against the minimap) and
  `tools/bake_roads.lua` derives the edge ratios. Neither database holds terrain or roads.
